0 · 背景：一次真实慨封锁事件

2026-08-01，Hermes Agent 慨主力 OpenRouter 帐户突然被Google、OpenAI、Anthropic 三厂联合封锁（403violation of provider Terms Of Service）。诊断结果：

测试结果结论
OpenAI 系（gpt-image-1 / gpt-5-image-mini）403 TOS帐户被永久标记（permanently flagged），与 IP / credits / 设定无关，retry 无效
Google 系（gemini-3-pro-image / gemini-3.6-flash vision）403 TOS
Anthropic（claude-sonnet-4）403 TOS
z.ai / Qwen / xAI / Meta 系正常文字 + 读图仍然可用

关键教训：唔好将全部 AI 能力押喺单一第三方平台。 OpenRouter 系聚合商，帐户一被标记就全线失效。与其开新帐户（有同 IP 关联风险），不如迁去基础设施商 Cloudflare — 渠系 DNS/CDN 供应商，唔会因「AI 内容政策」封你。

2 · 生图管线（免费，每日 ~170 张）

核心：CF flux-1-schnell 做主力，Pollinations.ai 做后备。 Pollinations 完全免费无 key（unlimited-ish），质素中等；CF flux 质素高，有明确每日额度。

2.1 费用估算（实测 pricing 页）

模型成本每日张数（1​​0k neurons）用途
flux-1-schnell~57.6 neurons/张（1024², 4 steps）~170日常主力
flux-2-klein-4b~104 neurons/张~90快 + 平
flux-2-klein-9b~1,364 neurons/张~7图生图专用（贵，悭住用）

2.2 核心 call（直连 API，唔使部署 Worker）

# 生圖 — POST /ai/run/<model>，JSON body
curl -X POST "https://api.cloudflare.com/client/v4/accounts/$CF_ACCOUNT_ID/ai/run/@cf/black-forest-labs/flux-1-schnell" \
  -H "Authorization: Bearer $CF_WORKERS_AI_TOKEN" -H "Content-Type: application/json" \
  -d '{"prompt":"a red apple on a wooden table","steps":4}'
# 回傳 {"result":{"image":"<base64>"}} → base64 解碼即係圖片

3 · 图生图（FLUX.2 慨隐藏技巧）

⚠️ 最易踩慨坑：CF 慨flux-2-klein-9b收图生图，但唔系 JSON— 用 JSON 传image会出400 Type mismatch。渠慨 schema 系multipart/form-data！
# 正確做法：-F multipart，image 用檔案上傳
curl -X POST ".../ai/run/@cf/black-forest-labs/flux-2-klein-9b" \
  -H "Authorization: Bearer $CF_WORKERS_AI_TOKEN" \
  -F "prompt=同一個場景，但女仔而家伏喺沙灘上，golden hour" \
  -F "image=@reference.jpg"        # ← multipart 檔案，唔係 base64！
# → 直接回傳編輯後嘅圖（base64）

呢个系成个迁移最关键慨发现：img2img 用 multipart，txt2img 用 JSON。用 Pythonrequests就系files={"image": (name, f, "image/jpeg")} + data={"prompt": ...}。

4 · 读图管线（双 gemma-4 通道）

Hermes 慨 vision fallback 原本会跌返去主 model（deepseek-v4-pro），而 deepseek 系纯文字— 收咗图但「睇唔到」（实测渠慨 reasoning 话I don't see any image attached）。解法：显式设定 aux vision provider。

# config.yaml — 主力：OpenRouter gemma-4:free（26B，免費 :free 唔受三廠封鎖影響）
auxiliary:
  vision:
    provider: openrouter
    model: google/gemma-4-26b-a4b-it:free

后备：CF 版同一个 model（@cf/google/gemma-4-26b-a4b-it，OpenAI-compatible messages 格式）— 写成cf_vision.py，gemma 主力失效时自动顶上。性能排名（实测）：

排名模型规格实测
🥇 主力gemma-4-26b-a4b-it:free（OpenRouter）26B（4B active MoE）详细准确
🥈 后备gemma-4-26b-a4b-it（CF）同一 model 唔同 host正常
❌moondream3.1 / llava-1.5（CF）9B / 7B空回传 / 400

5 · 存档系统（Drive + R2 双轨）

📁 Google Drive（5TB）每次生图自动 upload 去AI-images/YYYY-MM/，并写入images_index.jsonl记录 prompt + Drive link。用现有 google-workspace OAuth，零新设定。
☁️ Cloudflare R2（10GB）ai-imagesbucket，S3-compatible API（boto3）。超过 50%（5GB）自动删最旧到 4GB，每日 03:00 cron。
# R2 = S3-compatible：endpoint 用 account ID
endpoint = f"https://{R2_ACCOUNT_ID}.r2.cloudflarestorage.com"
s3 = boto3.client("s3", endpoint_url=endpoint,
                  aws_access_key_id=R2_ACCESS_KEY_ID,      # 32 字元
                  aws_secret_access_key=R2_SECRET_ACCESS_KEY)  # 64 字元
s3.create_bucket(Bucket="ai-images")   # 免費 plan 都得
s3.upload_file(path, "ai-images", name)  # 零 egress 費用

8 · 踩坑合集（全部亲测）

  • 403 TOS 唔一定系内容问题— 连「a red apple」都被拒 = 帐户层面封锁，retry 冇用。用非 Google/OpenAI/Anthropic 模型（z.ai/qwen/xAI）即刻确认。
  • OpenRouter :free 模型唔受三厂封锁影响—gemma-4-26b-a4b-it:free系读图最佳免费选择。
  • CF flux-2-klein-9b 用 multipart 唔系 JSON— JSON 传 image 会 400。
  • CF 官方 model list 有 ≠ 用得— moondream 空回传、llava 400（Beta）；gemma-4 顶上。
  • Flux 固定输出 1024×1024— 要 4:5 / 16:9 就要用 PIL 中心裁剪（width/height 参数系无效慨）。
  • deepseek 收图但睇唔到— 纯文字 model；aux vision 要显式设 vision-capable model。
  • curl 传大 base64 图会「Argument list too long」— 写 JSON body 落 file 再用-d @file。
  • 免费 tier 得 1 个并行请求— batch 要加 sleep，否则排队。

10 · 补充建议（由可用变成 production-ready）

以下系工程师覆核后慨补充 — 聚焦「可用 → production-ready」慨细节：凭证最小权限、重试策略、成本控制、后备深度、双轨对账。

10.1 凭证安全：Token 最小权限 + Rotation

  • Workers AI Token— 「Account → Workers AI → Edit」已经系最细权限；如有多个 project，建议开Account-scoped（而唔系 User-scoped），方便 revoke 时唔影响其他用途。
  • R2 S3 Token— 可以开「Object Read & Write only」（唔使 Admin），并且设指定 bucket（ai-images）— 即使 token 泄漏都只系得一个 bucket 慨权限。
  • Rotation 策略— 建议每90 日rotation 一次；CF API Token 可以开多个，新旧并行一阵再删旧，唔会断服务。

10.2 重试策略：唔系净系 sleep

免费 tier 得 1 个并行，实际会遇到三种情况：

情况HTTP Status处理建议
Rate limit429读Retry-Afterheader，跟渠等
排队中（极慢）200设timeout=60s，超时即视为失败 fallback
模型暂时不可用500 / 503即时 fallback 去 Pollinations，唔使 retry
# gen_image.py 加 retry decorator，但 429 唔應該 blind retry
@retry(
    stop=stop_after_attempt(3),
    wait=wait_exponential(multiplier=1, min=2, max=10),
    retry=retry_if_exception_type((
        requests.exceptions.Timeout,
        requests.exceptions.HTTPError
    ))
)

重点：429 要读Retry-After，否则会越踩越重。

10.3 Flux steps × neurons 慨非线性关系

§2.1 慨 57.6 neurons 系 4 steps 数值 — steps 对成本影响好大：

Steps~Neurons/张质量建议场景
1~20草稿级快速 preview、测试 prompt
4~58可用日常主力（原指南建议）
8~110较好重要输出
20~260最佳极少需要，不如用 flux-2-dev

悭 neurons 技巧：batch 生成（例如一次出 10 张变体），可以先用step=1做 preview，用户拣中先出step=4/8，悭大量 neurons。

10.4 Pollinations fallback 慨隐藏限制

  • 无 key ≠ 无限制— 单一 IP 有隐性 rate limit（约 10 req/min），超过会 return 空或极慢。
  • 无 SLA— 有时会 down 几分钟，fallback 逻辑要处理 timeout。
  • Prompt 兼容性— weight syntax（如(...:1.2)）可能唔支援；建议保持 prompt 简洁，唔用进阶语法。

建议 fallback 顺序：CF flux → Pollinations → 本地 SD（如有）→ 文字描述代替。

10.5 R2 与 Drive 双轨慨一致性

  • Drive 系「写入后即忘」— 上传成功就完，冇 checksum。
  • R2 可以验证— upload 后用head_object读 ETag，同本地 file 慨 MD5 比对。
# gen_image.py 生成後寫 manifest.jsonl（每行一條，方便日後對賬）
{"timestamp":"...","prompt":"...","drive_id":"...","r2_key":"...","md5":"...","model":"flux-1-schnell","neurons":57.6}

R2 cleanup 删旧档时，最好连 manifest 一齐标记deleted: true，而唔系真系删 manifest entry，保留 audit trail。

10.6 图片 metadata：EXIF 写入 prompt

# 用 PIL 將 prompt、model、timestamp 寫入 PNG 嘅 tEXt chunk
from PIL import Image, PngImagePlugin
img = Image.open("/tmp/cat.png")
metadata = PngImagePlugin.PngInfo()
metadata.add_text("prompt", prompt)
metadata.add_text("model", "flux-1-schnell")
metadata.add_text("generated_at", datetime.utcnow().isoformat())
img.save("/tmp/cat.png", pnginfo=metadata)

咁样即使 manifest 遗失，都可以从图片本身读返原始 prompt，方便 reproduce。

10.7 CF Workers AI 慨「隐藏」endpoint：AI binding

原指南用直连 API（/ai/run/...）。如果已部署 Cloudflare Worker，可以用 AI binding：

// worker.js
const response = await env.AI.run(
    '@cf/black-forest-labs/flux-1-schnell',
    { prompt: "..." }
)

好处：唔使管理 token（binding 用 account 权限）、可以做 caching、rate limiting、auth 层。坏处：要部署 Worker，多一层 infra。对于 Hermes 慨 use case，直连 API 已经够简洁；但如果将来要开 API 畀多人用，binding 方式会更易管理 quota。

总结：fallback 要够深。由 OpenRouter 三厂封锁学到慨教训，同样适用于 CF（免费 tier 有 quota、有并行限制、有偶发性 500）。多一层后备，少一层深夜 debug。
